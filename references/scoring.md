# 修为评定规则

## 1. 修为衡量什么

| 维度 | 含义 | 数据来源 |
|---|---|---|
| 上限 | 能独立搞定的问题难度在上升 | 宗门任务日志的难度、秘境修为 |
| 准确 | 同难度下判断失误更少 | 神识（第一判断正确率）、秘境得分 |
| 速度 | 同难度下从开始到做对的时间更短 | 任务耗时、秘境用时 |

修炼速度 = 上述指标滑动平均的斜率。

## 2. 宗门任务日志（每天约 15 分钟）

文件：`daily/YYYYMMDD.yaml`，由 `cultivate.py day` 从模板生成，宿主自己填写。

难度按客观特征打分，每项 0~3，求和得任务难度（0~12）。**禁止按"感觉难不难"打分**。宿主变强后，原来难的事会感觉不难，如果按感觉打分，难度会跟着能力一起涨，进步就被抵消了。

| 特征 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| modules 涉及模块数 | 1 个函数内 | 1 个模块 | 2~3 个模块 | 跨服务/跨系统 |
| unknowns 开始时关键未知点数 | 0 | 1 | 2~3 | ≥4 |
| clarity 需求清晰度 | 完全明确 | 小部分需自己定 | 大部分需自己定 | 问题本身需自己定义 |
| novelty 领域新旧 | 熟悉 | 部分新 | 大部分新 | 全新领域 |

跨天任务在完成当天记录，`actual.hours` 填累计耗时。`actual.done` 留空视为未完成，不计入统计。

派生指标：

- 一次做对：`done == true` 且 `first_judgment_correct == true`。
- 耗时预测误差：`abs(actual.hours − predict.hours) / predict.hours`。

## 3. 秘境（每周三处）

| 秘境 | 内容 | 默认时限 | 品阶特征（每项 0~3） |
|---|---|---|---|
| 除魔 debug | 真实 bug 与注入 bug 混用，给出代码快照与现象或失败测试，定位根因 | 90 分钟 | distance 现象与根因距离（同函数/同文件/跨文件/跨模块）、bug_kind bug 类型（逻辑/边界/生命周期/并发）、repro 复现难度、knowledge 背景知识 |
| 藏经 read | 读一个模块，写出关键调用链和数据流 | 60 分钟 | size 规模、indirection 间接层数（虚函数/回调/模板）、async 异步程度、knowledge 领域知识 |
| 炼器 design | 不依赖业务背景的通用设计题 | 60 分钟 | constraints 约束数、concurrency 并发、performance 性能、tradeoffs 权衡点数 |

秘境品阶 level = 四项特征之和（0~12）。

### 评分

每处秘境得分 s ∈ [0, 1]，用时另记。

| 秘境 | 评分 |
|---|---|
| 除魔 | 根因正确且在时限内：1；定位到正确函数但原因不对：0.5；未找到或超时：0 |
| 藏经 | 天机里的要点清单，s = 命中数 / 总数 − 0.1 × 错误断言数，下限 0 |
| 炼器 | 需求覆盖、接口设计、边界与并发处理、权衡说明、简洁性，五项各 1~5 分，s = 总分 / 25 |

## 4. 修为（Elo）

```
秘境难度分 D = base + level × step = 1000 + level × 75
期望得分   E = 1 / (1 + 10^((D − R) / 400))
新修为     R' = R + K × (s − E)，K = 32
```

- 除魔、藏经、炼器各一条修为，另有一条总修为（所有秘境按时间顺序更新）。
- **测灵根**：每条修为的前 3 个有成绩的周为测灵根期。期满时用这 3 周全部成绩求表现分（解方程 ΣE(R, Dᵢ) = Σsᵢ）作为初始修为，之后逐题按 K = 32 更新。测灵根期只显示暂估修为，不画修为曲线。全对或全错时方程无解，取 max(D) + 400 或 min(D) − 400。
- **建议品阶**：level ≈ (R + 100 − 1000) / 75，比当前修为略高。测灵根期按 level 4~6 出题。

## 5. 境界

| 大境界 | 修为 |
|---|---|
| 练气 | < 1200 |
| 筑基 | 1200 ~ 1400 |
| 金丹 | 1400 ~ 1600 |
| 元婴 | 1600 ~ 1800 |
| 化神 | ≥ 1800 |

每个大境界的 200 分平均分为初期、中期、后期、大圆满，每段 50 分。例如 1260 为筑基中期。练气没有下限，小境界按 1000~1200 划分，低于 1050 都算练气初期。化神没有上限，小境界按 200 分一轮循环。

升一个大境界需要多 200 分。在同一品阶的秘境上，期望得分大约从 0.5 升到 0.76。

`cultivate.py score` 在小境界或大境界变化时输出"突破"或"跌境"，测灵根期满时输出"灵根测定完成"。

## 6. 照心镜（每月约 30 分钟）

文件：`retro/YYYY-MM.yaml`，由 `cultivate.py retro` 生成。宿主挑一段自己 2~3 个月前写并合入的代码重读，记录现在能看出的问题：severe 会导致错误或隐患，normal 是设计或可维护性问题，minor 是风格与细节。

加权问题数 = 3 × severe + 2 × normal + minor。现在能看出的问题越多，说明眼界越高。这个指标受当时阅读的仔细程度影响，只作参考。

## 7. 修为面板

`cultivate.py report` 生成 `report/index.html`，单文件，图片内嵌。

| 图 | 内容 |
|---|---|
| 境界卡片 | 总修为与三类秘境修为、当前境界、测灵根进度 |
| 修为曲线 | 测灵根后的周度修为，背景为大境界 |
| 秘境战绩 | 每处秘境的得分、用时占时限比 |
| 能力边界图 | 横轴任务难度分桶，纵轴一次做对比例，每季度一条线，右移代表上限变高 |
| 同难度耗时 | 每个难度桶的月度耗时中位数 |
| 神识 | 周度第一判断正确率与耗时预测误差，带 4 周滑动 |
| 心境 | 日度状态分与 7 日均线 |
| 季度道基图 | 雷达图：三类秘境修为（(R−1000)/1000 截断到 0~1）、判断正确率、照心镜（按各季度最大值归一） |
